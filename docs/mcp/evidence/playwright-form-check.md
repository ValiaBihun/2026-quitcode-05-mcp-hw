# Перевірка форми заявки через Playwright MCP

Дата: 2026-10-11, 16:39–16:40. Claude Code 2.1.296 у терміналі (`claude` у теці репозиторію), модель Sonnet 5.5,
режим дозволів `default` (запит на кожен виклик, не з `allow`). Сервер `playwright` з `.mcp.json`
(`@playwright/mcp@0.0.82`, `--isolated`, `--no-webmcp`, `--allowed-origins http://localhost:3000`), правила з
`.claude/settings.json`.

## Сесія була чистою

- У `/mcp` увімкнено лише `playwright`; project-сервери `supabase` і `vercel` та конектори claude.ai (Claude Docs,
  Supabase, Vercel) вимкнено. Знімок `/mcp` зроблено перед запитом.
- Журнал сесії не містить жодної згадки інструментів Supabase, Vercel, Claude in Chrome чи вбудованого браузера
  застосунку. З claude.ai у сесії лишилися лише шість конекторів без входу (Airtable, Gmail, Make, Zite, draw.io,
  n8n), кожен із двома заглушками для входу (`authenticate`, `complete_authentication`); даних вони не дають.
- Агент не мав потреби в shell і не запускав його: dev-сервер (`npm.cmd run dev`; у PowerShell `npm.ps1`
  заблоковано політикою виконання скриптів) користувачка запустила в окремому вікні заздалегідь.

## Запит

> Відкрий http://localhost:3000, заповни форму заявки тестовими даними, відправ, перевір консоль і мережу. Інших адрес не відкривай. Сервер уже працює, команди в shell не запускай.

Останнє речення додано навмисно, щоб агент не запускав сервер сам (у попередній спробі це закінчилося осиротілим
процесом, див. нижче).

## Ланцюжок інструментів

Перелік узято з журналу сесії, а не зі слів агента.

| # | Інструмент | Що робив |
|---|---|---|
| 1 | `browser_navigate` | відкрив `http://localhost:3000` |
| 2 | `browser_snapshot` | знімок сторінки, щоб побачити поля форми |
| 3 | `browser_fill_form` | заповнив поля вигаданими даними, вибрав бюджет |
| 4 | `browser_click` | натиснув «Надіслати заявку» |
| 5 | `browser_snapshot` | знімок після відправки |
| 6 | `browser_console_messages` | прочитав консоль |
| 7 | `browser_network_requests` | список мережевих запитів (параметр `static: false`) |

Усього 7 викликів Playwright, усі успішні. Крім них — один `ToolSearch` (завантажити схеми інструментів). Викликів
`Bash` немає. Запитів на дозвіл, які користувачка відхилила, немає; «Always allow» не обирали (у
`.claude/settings.local.json` правил `allow` немає).

## Чи відправилась форма

Так. На знімку після кліку є «Дякуємо! Заявку отримано.». Дані вигадані. Заявка лежить лише в пам'яті dev-сервера
(`lib/db.ts`).

## Консоль

Два записи, обидва інформаційні: підказка про React DevTools і `[HMR] connected`. Помилок і попереджень немає.
Збігається з журналом консолі, який зберіг Playwright (`.playwright-mcp/`).

## Мережа

- Єдиний показаний запит: `POST http://localhost:3000/` зі статусом 200: це Server Action форми.
- Інструмент додав примітку «22 static requests not shown»: виклик ішов зі `static: false`, тож 22 статичні запити
  приховано, агент їх не відкривав, а повного переліку їхніх адрес ми **не отримали**. Тому підтверджено лише таке:
  у показаному запиті, у журналі консолі й у знімках сторінки зовнішніх адрес немає. Що **усі** запити сторінки йшли лише
  на `http://localhost:3000`, ці докази не підтверджують.
- Додаткова перевірка без браузера (не заміна повного переліку): HTML головної сторінки з працюючого dev-сервера містить
  18 ресурсів в атрибутах `src`/`href` (14 скриптів, 1 стиль, 1 іконка, 2 інші), і всі вони з відносними адресами, тобто
  з того самого `localhost:3000`; жодного рядка `http://` чи `https://` у HTML немає. Це не охоплює ресурси, які
  браузер підвантажує вже після цього (шрифти зі стилів, динамічні чанки).
- Щоб отримати повний перелік, потрібен окремий прогін Playwright з `browser_network_requests` і `static: true`.
  Ми його не повторювали.

## Прибирання після перевірки

Вікно Chrome від Playwright закрито. Вікно з dev-сервером після завершення сесії знайти не вдалося, тому дерево
процесів сервера зупинили командою `taskkill /T /F` (після перевірки, що це сервер цього проєкту). Перевірено:
порт 3000 вільний, процесів `next` цього проєкту немає, процесів Chrome з ознаками Playwright немає.

## Попередня спроба (15:39), замінена цією

Першу перевірку провели в сесії, де поряд із `playwright` були ввімкнені project-сервери `supabase` і `vercel`:
викликів Supabase не було, але це порушує правило «браузерний сервер ніколи не працює в одній сесії з Supabase».
Тому її повторили в чистій сесії. Що ще показала та спроба:

- Агент сам запустив `npm run dev` через shell, бо порт 3000 не відповідав.
- Після перевірки він зупинив сервер інструментом `TaskStop` і повідомив «stopped». Насправді зупинилась лише
  обгортка: процес `node` з `next dev` лишився й слухав порт 3000, а сторінка в Chrome Playwright була підключена до
  нього. Дерево процесів зупинили окремо (`taskkill /T /F`). Висновок: «агент каже, що зупинив» і «зупинено» — не
  одне й те саме, результат дії треба перевіряти.
- Підсумковий рядок Claude Code казав «Called playwright 7 times», у переліку агента було 8 викликів: перший
  `browser_navigate` завершився помилкою `ERR_CONNECTION_REFUSED` (сервера ще не було), тож Claude Code порахував лише
  успішні.
